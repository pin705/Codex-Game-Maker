# Game Studio Accessibility

Treat accessibility as player-path coverage, not a settings-page label.

## Required Output

Create `design/accessibility/accessibility-conformance.json` from `../../references/templates/accessibility-conformance.json`.

## Workflow

1. Scope barriers across vision, hearing, mobility, speech, cognition, photosensitivity, and motion sensitivity for the declared game and platforms.
2. Define required features: readable scalable text, contrast, non-color cues, subtitles/captions, audio alternatives, remapping, focus/navigation, timing/difficulty assists, motion/shake controls, photosensitivity protection, and accessible help/support as applicable.
3. Ensure accessibility options are reachable before gameplay and persist correctly.
4. Test keyboard, controller, touch, assistive input, screen narration/platform features, language expansion, busiest gameplay, failure, and recovery.
5. Record feature-level runtime evidence and limitations. Keep store accessibility declarations exactly aligned.
6. Include players with relevant lived experience or a qualified accessibility review before commercial approval.

Keyboard-only navigation is not full accessibility. Missing critical alternatives, unreachable settings, false store claims, untested captions, uncontrolled flashing/motion, or absent required player review block commercial release.
